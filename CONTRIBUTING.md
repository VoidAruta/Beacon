# Руководство для контрибьюторов / Contributing Guide

Спасибо за интерес к развитию **Beacon (`VoidAruta/Beacon`)** — автономной панели управления скриптами и демонами для домашних серверов на базе Android (Linux chroot).

## Незыблемые архитектурные правила (Architecture Invariants)

При внесении изменений в ядро (`hub/`) обязательно соблюдайте следующие ограничения целевой платформы (смартфон в круглосуточном режиме 24/7, ARM64 `aarch64`, отсутствие systemd внутри chroot):

1. **Управление группами процессов (`os.setsid()` + `os.killpg()`):**
   - Каждый запускаемый проект должен стартовать в новой сессии (`os.setsid` в `preexec_fn`), чтобы его `PGID` совпадал с `PID` лидера.
   - Остановка процесса всегда выполняется через `os.killpg(pgid, signal.SIGTERM)` с последующим `SIGKILL` по таймауту. Обычный `proc.kill()` запрещён, так как оставляет процессы-сироты (например, дочерние браузеры или `python3`, порождённые из `bash -c`).
2. **Никаких `subprocess.PIPE` для логов длительных процессов:**
   - Потоки `stdout` и `stderr` дочерних проектов должны перенаправляться напрямую в открытый файловый дескриптор лога (`buffering=0`).
   - Это гарантирует, что при перезапуске или обновлении самого процесса Hub дочерние 24/7-боты не упадут от `SIGPIPE` и не зависнут при заполнении буфера пайпа ядра (64 КБ).
3. **Защита от PID Reuse при восстановлении процессов:**
   - В `recover_running_processes()` при сверке живых PID из базы данных обязательно проверяйте время создания процесса через `psutil.Process(pid).create_time()` (допуск `<= 2.0` сек относительно `started_ts`).
4. **Никаких `RLIMIT_AS` для контроля памяти:**
   - Не используйте `resource.setrlimit(resource.RLIMIT_AS, ...)`. Среды с JIT и резервированием виртуального адресного пространства (Node.js/V8, JVM, Go, Chromium) мгновенно падают при старте.
   - Контроль `max_ram_mb` осуществляется в фоновом цикле путём суммирования реального физического потребления (`memory_info().rss`) всех процессов внутри группы `PGID`.
5. **Сохранение сетевых групп Android (`3003`, `3004`):**
   - В ядре Android доступ к сокетам контролируется патчем `CONFIG_ANDROID_PARANOID_NETWORK`. При понижении привилегий (`os.setuid` / `os.setgid`) до пользователя `runner` обязательно сохраняйте дополнительные группы `aid_inet` (`3003`) и `aid_net_raw` (`3004`), иначе дочерние скрипты получат `PermissionError: [Errno 13] Permission denied` при любом сетевом запросе.
6. **Бюджет ресурсов:**
   - Потребление ОЗУ самим процессом Hub в покое не должно превышать **80 МБ**.
   - Разрешены только легковесные библиотеки с готовыми бинарными колёсами (`manylinux_aarch64`) без необходимости компиляции C/Rust на телефоне и без внешних брокеров (Redis, PostgreSQL, RabbitMQ, Docker).

## Локальная разработка и проверка

### 1. Запуск бэкенда (Python 3.11+)
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python3 -m hub
```
По умолчанию сервер слушает `http://127.0.0.1:8050`.

### 2. Разработка фронтенда и сборка статики
На самом телефоне Node.js не требуется — готовая статика лежит в `hub/static/`. Если вы меняете интерфейс в `src/`:
```bash
npm install
npm run build:static
```
Команда `npm run build:static` компилирует React/Tailwind-приложение напрямую в `hub/static/`, после чего `python3 -m hub` раздаёт обновлённый интерфейс без участия Node.js.

### 3. Требования к Pull Request
- Проверьте, что в коммит не попали файлы из `data/` (`hub.db`, `secret.key`, `cookies/`, `logs/`) и пользовательские папки из `projects/` (кроме `projects/examples/`).
- Убедитесь, что все тесты проходят:
  ```bash
  npx tsx --test src/utils/hubLogic.test.ts
  ```
- Опишите в PR сценарий проверки на целевом устройстве (Android chroot / Linux ARM64).
